# وثيقة التعديل الهندسي (Architecture Decision Record - ADR-002)
## اعتماد منصة Supabase كبنية تحتية موحدة لقواعد البيانات والخدمات الخلفية

- **رمز القرار الهندسي:** ADR-002-SUPABASE-BACKEND
- **تاريخ الاعتماد:** 2026-09-17
- **الحالة:** معتمد (Approved & Adopted)
- **المرجعية:** موافقة وتوجيه المالك / المشرف الهندسي للمشروع
- **الأقسام المرتبطة في الوثيقة V1:** البند 17 (Architecture & Schema)، البند 18 (RBAC & Governance)، البند 48 (Atlas & Shrines).

---

### 1. السياق والمشكلة (Context & Problem Statement)
تتطلب منصة «السبع المثاني وعقد التمام» بنية تحتية خلفية لإدارة شبكة معرفية هائلة (Knowledge Graph) تتضمن الأنساب النبوية، سلاسل الإسناد العلمي والروحي، الإجازات، الروايات، المراقد، والرحلات، مع تطبيق صارم لقواعد "المصدر أولاً" (Source-First) وحوكمة التدقيق والتحقيق التشاركي (Collaborative Verification Workflow).
تم إجراء تقييم مقارن بين خيارين أساسيين:
1. **Google Firebase:** نموذج NoSQL Document Store سحابي مغلق.
2. **Supabase (Open-Source):** نموذج PostgreSQL Relational & Object-Relational مفتوح المصدر يدعم الامتدادات المتقدمة والأمان على مستوى الصفوف (Row-Level Security - RLS).

---

### 2. القرار الهندسي المعتمد (The Decision)
**اعتماد Supabase كمنصة معتمدة وحصرية للخدمات الخلفية وقاعدة البيانات للمشروع.**

#### مرتكزات القرار وأسباب التفضيل:
1. **التطابق البنيوي مع مخطط البيانات (Relational Alignment):**
   - المخطط الشامل للمنصة تم تصميمه بالفعل في ملف الهجرة (`database/migrations/001_initial_schema.sql`) بصيغة PostgreSQL قياسية (24 جدولاً، مفاتيح أجنبية، وفهارس ربط).
   - اعتماد Supabase يسمح بتشغيل واستيراد هذا المخطط مباشرة بنسبة 100% دون الحاجة لإعادة هندسة أو تفكيك البيانات إلى NoSQL Denormalized Structures.
2. **الاستعلامات العودية الشجرية (Recursive Graph Queries):**
   - قدرة محرك PostgreSQL في Supabase على تنفيذ استعلامات `WITH RECURSIVE` لجلب مسارات الأسانيد وشجرات النسب المتفرعة باستعلام مفرد عالي السرعة دون الوقوع في مشكلة `N+1 Queries`.
3. **أمان الصفوف عالي الدقة (Row-Level Security - RLS):**
   - حوكمة الوصول متعدد المستويات (زائر، محقق، مراجع، مدقق أعلى، مدير نظام) تُدار وتُنفذ في قلب محرك قاعدة البيانات عبر أوامر SQL، مما يضمن استحالة تسريب مسودات أو أدلة غير محققة.
4. **دعم اللغة العربية والأطلس الجغرافي (Extensions):**
   - الاستفادة من امتداد `pg_trgm` للبحث التقريبي في الأسماء والكنى والمصادر العربية.
   - الاستفادة من امتداد `postgis` لحساب مسافات الرحلات الجغرافية وإحداثيات أطلس المعالم والمراقد بدقة مكانية هندسية.
5. **سيادة البيانات ومنع الارتهان (No Vendor Lock-in):**
   - كون المنصة مفتوحة المصدر يتيح للجهة المالكة إمكانية تشغيلها على خوادم سحابية خاصة أو استضافتها ذاتياً (Self-Hosted via Docker) في أي وقت دون تبعية تجارية أو تقنية مغلقة.

### 4. الإجراءات الفنية والتنظيمية المترتبة
1. توثيق متغيرات البيئة الخاصة بـ Supabase (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`) في ملف التوثيق والبيئة التوضيحي.
2. تحديث شاشة "عن المنصة" وقسم التوثيق المعماري ليعكس اعتماد معمارية PostgreSQL / Supabase المفتوحة المصدر.
3. الإبقاء على عقود الواجهات البرمجية (REST API Contracts) دون أي تغيير سطحي لضمان استمرارية تجربة المستخدم وواجهات الواجهة الأمامية دون انقطاع.
